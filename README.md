# 点证 Pointwise Delivery — 多指标工艺决策数据应用

一个零外部依赖的全栈示例：导入虚构工艺方案、指标方向、联合场景和测量费用，判断：

- **确定被支配**：存在另一方案，在 *每一个同一联合场景* 中都不劣于它，且至少一维严格更好；
- **可能有效**：存在一组位于偏好范围内的权重和一个联合场景，使该方案加权得分最高，并返回可核验见证；
- **证据不足**：缺少联合场景/明确约束，或不可退让阈值尚不能在全部场景中稳健保证。

应用不会把成本、能耗、收率的边际区间端点拼成一个不存在的“最坏世界”，也不会在权重范围中偷偷选一组权重。

## 启动

```bash
./run.sh
# 或
python3 -m app.server
# 或
npm start
```

打开 <http://127.0.0.1:8000>。可用 `PORT=8123 ./run.sh` 改端口。

运行测试：

```bash
npm test
# 或
python3 -m unittest discover -s tests -v
```

运行独立小规模枚举核对：

```bash
npm run enumerate
# 或
python3 scripts/enumerate_check.py
```

后端仅使用 Python 标准库；前端是原生 HTML/CSS/JavaScript，不需要构建或访问外部 CDN。

## 页面能做什么

1. **改变权重范围**：每个指标可设置权重下限/上限。系统检查 `Σ lower ≤ 1 ≤ Σ upper`，不可行时明确报错。
2. **锁定硬阈值**：勾选锁定后，要求方案在所有剩余联合场景中稳健达标。提供“稳健常规红线”和“矛盾高压红线”预设。
3. **查看支配见证**：候选详情中可切换对照方案，逐场景、逐指标查看“候选优 / 对手优 / 相等”。任何一个反向单元格都会阻断对应方向的支配。
4. **查看最优见证**：返回具体权重、场景、全部分值和领先差距；该权重一定位于用户给定范围内。
5. **补入合成测量**：
   - 可点击测量目录中的虚构结果分支；
   - 也可自定义方案、指标、观测值、可信半宽和费用；
   - 联合方案会保留观测邻域内的联合场景；
   - 只有边际区间的方案即使缩窄单个区间，也仍标记证据不足，直到补入联合证据。
6. **比较追加测量**：展示费用、期望歧义下降、保底/最好分支、单位费用收益和 Pareto 前沿。
7. **前后解释**：每次补测后说明场景数、可能最优集合、歧义指数、状态变化和费用。
8. **导入自己的 JSON**：可下载当前虚构数据作为模板。

## 核心语义

### 联合场景，而不是端点笛卡尔积

示例数据中的每个场景都包含同一运行世界下所有方案的三项指标：

```text
scenario S1
└── values
    ├── P2: {cost: 4.6, energy: 12.5, yield: 91.5}
    ├── P3: ...
    └── ...
```

支配关系只比较同一场景中的 `P_i` 与 `P_j`。区间条仅展示这些联合点的 min/max 包络，并标注端点来自哪个场景。

测试 `test_joint_scenarios_prevent_impossible_worst_case_dominance` 构造了一个相关性陷阱：逐维拼出的最坏向量看似会被 B 支配，但在真实联合场景 S1/S2 中 A 分别有成本和能耗/收率反证，因此结论是 `tradeoff`。

### 权重范围中的存在性见证

指标先按固定 `scale` 转为方向一致的效用：

- 越小越好：`u = (scale_max - x) / (scale_max - scale_min)`
- 越大越好：`u = (x - scale_min) / (scale_max - scale_min)`

权重满足 `w_m ≥ 0`、`Σ w_m = 1` 和用户给出的 `[lo_m, hi_m]`。对固定场景，“A 最优”是一组线性不等式：

```text
Σ_m w_m (u_A,m - u_J,m) ≥ 0  for all J
```

`app/engine/linalg.py` 小规模枚举权重多面体的基解（和为 1 的等式加 `M-1` 个主动约束），因此返回的是数学上存在的见证，而不是中点权重。

### 决策歧义指数

界面明确展示公式：

```text
歧义指数 =
  max(0, 可能最优方案数 - 1)
  + 可能最优方案之间的未解决权衡对数
  + 联合证据缺口数
```

同时单独返回三个分量，避免把不同含义强行压成黑盒分数。测量建议会模拟每个虚构结果分支后的重算结果，给出：

- `expected_reduction`：按结果概率加权的期望下降；
- `guaranteed_reduction`：所有结果分支中的最小下降；
- `upside_reduction`：最好分支的下降；
- `roi`：期望下降 / 费用；
- Pareto 费用-收益前沿标记。

已经被稳健支配的方案，即使再加密其中点测量，也不会减少决策歧义；示例测量 M6 就是这种“缩窄区间但无决策价值”的反例。

## 示例数据中预埋的核对点

- `P1`、`P7`：确定被支配；
- `P2/P6`：五场景指标完全相同的平行方案，验证完全等价不会被误判为支配；
- `P2/P3/P4/P5/P6`：初始权重范围内均有最优见证；
- `P8`：只有边际区间、没有联合场景，初始为证据不足；M4 联合试生产可将其转为可能有效或被支配；
- “矛盾高压红线”：`cost ≤ 4.2` 且 `yield ≥ 95%`，枚举后没有任何同场景联合点同时满足；
- 小规模枚举：对单纯形权重网格、场景和方案做暴力打分，核对精确见证求解的候选集合。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 |
| GET | `/api/seed` | 获取内置虚构数据 |
| POST | `/api/analyze` | body：`{dataset?, options?}`，返回分类、支配对、见证、阈值冲突和歧义 |
| POST | `/api/recommend` | 返回测量建议及分支模拟 |
| POST | `/api/apply-measurement` | 应用预置结果分支或自定义合成测量，返回前后分析与解释 |
| POST | `/api/enumeration-check` | 独立网格枚举核对 |
| POST | `/api/validate-import` | 校验导入数据并返回摘要 |

`dataset` 缺省时使用内置示例；`options` 形如：

```json
{
  "weight_ranges": {"cost": [0.2, 0.55], "energy": [0.1, 0.5], "yield": [0.15, 0.55]},
  "thresholds": [
    {"metric_id": "cost", "op": "<=", "value": 5.6, "locked": true}
  ]
}
```
